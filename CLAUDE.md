# CLAUDE.md

Language courses, each a curriculum in a target language taught in a source language (the first: Brazilian Portuguese for English speakers, A1 to B2). A Rust workspace: `shared` (course model, validation, practice and review logic), `tools/course_builder` (validate, synthesize audio, write and publish SQLite bundles) `web` (Leptos, server render plus client hydration, run with `cargo leptos watch`), `ffi` (the core exposed to native apps through UniFFI) and `ios/` (a SwiftUI app generated by XcodeGen from `ios/project.yml`; the `.xcodeproj` is not committed).

## Conventions

Follow `docs/conventions/` (type naming, log format, conditional compilation) and the owner's global `~/.claude/CLAUDE.md`. Scripts in `scripts/` wrap the tools; use them.

## Visual design

Follow `docs/design.md` (Eafora's identity): tokens in `web/style/_tokens.scss`, no raw colors or sizes elsewhere, no shadows, no rounded corners, no animation.

## Course data

- Author units to the format in `docs/authoring.md`, then run `cargo run --package course_builder -- validate --course <course id> <unit-id>`. The validator is the authority on structure; `shared/tests/course_data.rs` fails `cargo test` if any unit is invalid.
- Courses live in `data/courses/<course id>/` (`curriculum.json` plus `units/`); a course id is `<target language>.<source language>.<curriculum name>`. `target` fields are in the language taught, `source` fields in the language it is taught in, `source_literal` is the word-for-word gloss.
- Every `target` string is spoken by text-to-speech, so it must be plain speakable text.
- A target language can add its own checks (`shared/src/course/target_language_rules.rs`); for `pt-BR`, European forms in `target` fields are rejected by the validator.
- A new target language needs speech voices in `tools/course_builder/src/speech_engine/speech_language.rs`.
- `build/` (clip store, bundles, local repository) and `web/static/embedded/` are generated and not committed.

## Running locally

`./scripts/dev/serve.sh` needs only this machine. `course_builder build` synthesizes every clip with each engine (Kokoro through ONNX Runtime and eSpeak NG, with model files downloaded once into `models/`, and the macOS `say` voices), encodes with `ffmpeg` into `build/clips/<engine>/`, and writes one bundle per course to `build/artifacts/<course id>/<publication label>/`. A clip's key depends only on its persona and text; a change to an engine's pipeline bumps `pipeline_revision`, which discards that engine's clips. `publish local` copies each course's bundle into `build/repository/`, which `repository_server` serves at http://127.0.0.1:3002, the address the committed `web/static/discovery` names.

## Architecture

`docs/architecture/overview.md` describes the artifact contract (course index, course manifests, shards, publish order, discovery, client loading). The shard schema is `shared/src/course_shard/*.sql`; for a change a reader must detect, bump `SCHEMA_VERSION` in `course_shard_schema.rs`, `COURSE_MANIFEST_SCHEMA_VERSION` in `shared/src/artifact/course_manifest.rs` or `COURSE_INDEX_SCHEMA_VERSION` in `shared/src/artifact/course_index.rs`.
